## 1. P2P接続とトポロジーの理解 [#sec-1]

P2P では接続先の多くはノードが自動で選びます。  
**必ずつなぎたい相手（自BP・自リレーなど）だけ** `localRoots` に書きます。

### 接続状態（Hot / Warm / Cold） [#sec-2]

ノードは接続先を次の3種類で管理します。

| 状態 | 説明 |
| --- | --- |
| **Hot** | ブロック同期・伝播に使っているアクティブな接続 |
| **Warm** | 接続は維持し、必要時に Hot に昇格する待機接続 |
| **Cold** | 候補として保持しているが、まだ接続していないピア |

**覚えておくとよいこと**

- `advertise`は`Peer Sharing`でその接続先を他ノードへ知らせてよいかを表します。  
- BPや内部用リレーなど、外部へ公開したくない接続先は `false`に設定。


リレーノードポートのFW許可
<Callout type="warn" title="VPS側のFWを使用している場合">
`ufw` は使わず、VPSの管理画面で**リレー用ポート（例: 6000）のインバウンド**を許可してください。
</Callout>
```
sudo ufw allow 6000/tcp
```
```
sudo ufw reload
```

<Callout type="info" title="BPのインバウンド通信を許可する必要がない理由">
Dynamic P2Pでは、**Duplex Connection（双方向接続）**により、BPからRelayへ確立した1本のアウトバウンド接続を双方向のノード間通信に利用できます。
そのため、BPのノードポートへの新規インバウンド接続をFirewallで許可しなくても、BPとRelay間の通信を維持できます。
これによりBPを外部から直接接続できない状態に置くことができ、攻撃対象となる範囲（Attack Surface）を縮小できます。

[Engineering dive into Cardano's Dynamic P2P design](https://www.essentialcardano.io/article/engineering-dive-into-cardanos-dynamic-p2p-design?utm_source=chatgpt.com)
</Callout>

## 2. トポロジーファイルの変更 [#sec-3]

この手順では、`GenesisMode` を使用する構成を前提としています。  
Genesis Modeでは bootstrapPeers を使用せず、リレーは peerSnapshotFile を使用してGenesis同期を行います。  
BPは自リレーのみに接続し、peerSnapshotFile は使用しません。

<Callout type="info" title="${NODE_CONFIG}-topology.json">


- **リレー** … 自BP・他リレーなど、固定したい相手を `localRoots` に記載。
- **BP** … **自リレーだけ**。`useLedgerAfterSlot` は **`-1`**（台帳ピアを使わない）。
- **IP** … サーバーの**パブリック（固定）アドレス**。ポートはノード用（SSH と混同しない）。

</Callout>


同期が 100% になってから以降の手順を実施してください。

```bash
cardano-cli latest query tip ${NODE_NETWORK} | grep syncProgress
```
```yaml title="期待される表示例：" noCopy
"syncProgress": "100.00"
```


### 主な項目 [#sec-4]

| 項目 | 説明 |
| --- | --- |
| **localRoots** | 常に維持したいピアのグループ（**グループ間で同じピアを重ねない**） |
| **accessPoints** | IP または DNS とポート |
| **advertise** | Peer Sharing でその接続先を他ノードへ知らせてよいか。BP や内部用リレーなど、公開したくない接続先は `false`に設定 |
| **trustable** | この手順では、BP用の自リレーグループは `true`、リレー用のグループは `false` に設定します。 |
| **hotValency** | そのグループの Hot 接続数（旧 `valency` と同義） |
| **diffusionMode** | UFW 等で通信元を制限している場合、`InitiatorOnly` は不要です。`diffusionMode` を省略すると `InitiatorAndResponder` になります。 |
| **peerSnapshotFile** | Genesis Modeの初期同期に使用するBig Ledger Peerのスナップショットファイル。 |
| **useLedgerAfterSlot** | リレーは手順例の値、BP は **`-1`** |

### 構文チェックと再起動 [#sec-6]

```bash
jq . $NODE_HOME/${NODE_CONFIG}-topology.json
```

JSON がそのまま表示されれば問題ありません。  
`parse error` のときは `{}` `[]` `,` を確認してください。

ノードを再起動します。
```bash
sudo systemctl reload-or-restart cardano-node
```
