---
title: "リレーノード構築(Nix)"
---

リレーノードは **Nix** を使用して構築します。

<Callout type="info" title="リレーでNixを使う理由">

- **テストネットのため、仕様やバージョンが都度変更される可能性がある** … Nix なら `nix run github:input-output-hk/ouroboros-leios#leios-testnet-relay` を再実行するだけで、最新の構成（ノード・設定・監視スタック）に追従できます。
- **セットアップ作業工数の軽減** … 依存関係のインストールやソースからのビルドが不要で、ノードと監視スタックをワンコマンドで一括起動できます。

</Callout>


<Callout type="info" title="このページで行うこと">

1. Nix のインストールと flakes の有効化
2. 作業ディレクトリの準備
3. リレーノードの起動（動作確認）
4. tmux による常駐化
5. 同期状況の確認

</Callout>


## 1. Nixのインストール [#sec-1]

Nix パッケージマネージャをインストールします。

```bash
curl --proto '=https' --tlsv1.2 -L https://nixos.org/nix/install | sh -s -- --daemon
```

セッションの再起動
```
exec $SHELL
```

インストールを確認します。
```bash
nix --version
```
```yaml title="期待される表示例：" noCopy
nix (Nix) 2.x.x
```


## 2. flakesの有効化 [#sec-2]

Leios のコマンドは flakes 機能を利用するため、有効化します。

```bash
echo "experimental-features = nix-command flakes" | sudo tee -a /etc/nix/nix.conf
echo "accept-flake-config = true" | sudo tee -a /etc/nix/nix.conf
echo "trusted-users = $(whoami)" | sudo tee -a /etc/nix/nix.conf
sudo systemctl restart nix-daemon
```

<Callout type="info" title="trusted-users の設定について">

`trusted-users` を設定しないと、IOG のバイナリキャッシュ（`cache.iog.io`）が利用されず、`you are not a trusted user` という警告とともに、すべてをソースからビルドすることになり非常に時間がかかります。  
必ず設定し、`nix-daemon` を再起動してください。

</Callout>


## 3. 作業ディレクトリの準備 [#sec-3]

作業ディレクトリを環境変数に設定します。  
`WORKING_DIR` には、ノードのDBや設定ファイル、ソケットが配置されます。

```bash
echo 'export WORKING_DIR=$HOME/leios-relay' >> $HOME/.bashrc
echo 'export CARDANO_NODE_NETWORK_ID=164' >> $HOME/.bashrc
echo 'export CARDANO_NODE_SOCKET_PATH=$HOME/leios-relay/node.socket' >> $HOME/.bashrc
source $HOME/.bashrc
mkdir -p "$WORKING_DIR"
```

<Callout type="info" title="設定ファイルについて">

リレーは `nix run github:input-output-hk/ouroboros-leios#leios-testnet-relay` を使用します。  
このコマンドが **ノード・設定ファイル・監視スタック（Grafana / Prometheus / Loki）を一括で用意し、`$WORKING_DIR` 配下に配置** するため、設定ファイルを手動で取得する必要はありません。

</Callout>


## 4. リレーノードの起動（動作確認）[#sec-4]

まずはワンコマンドでリレーを起動し、正常に動作するか確認します。

```bash
nix run github:input-output-hk/ouroboros-leios#leios-testnet-relay
```

<Callout type="info" title="初回起動について">

- 初回はバイナリのダウンロード・ビルドに時間がかかる場合があります。
- 起動時に `allow-import-from-derivation` や `extra-substituters` の許可を求められた場合は `y` を入力してください。
- ノードに加えて監視用のダッシュボード（Grafana）が `http://localhost:3000` で起動します。

</Callout>


別のターミナルを開き、同期状況を確認します。

```bash
nix develop github:input-output-hk/ouroboros-leios#dev-testnet --command \
  cardano-cli query tip
```

```yaml title="期待される表示例：" noCopy
{
  "block": 12345,
  "epoch": 42,
  "era": "Dijkstra",
  "slot": 678910,
  "syncProgress": "100.00"
}
```

> `syncProgress` が `100.00` になればフル同期完了です。  
> 確認できたら `Ctrl+C` でいったんノードを停止します。


## 5. tmuxによる常駐化 [#sec-5]

`leios-testnet-relay` は **process-compose の対話的なダッシュボード（tip-watcher ペインをマウス／キーボードで選択できる画面）** を起動します。  
この画面は **TTY（端末）が必要** なため、TTY を持たない systemd 配下では利用できません。  
ペイン画面を使いながら常駐させるには、**tmux** でセッションを保持します。

<Callout type="warn" title="動作確認用プロセスの停止">

手順4で `nix run` を起動したままの場合は、ポート競合を避けるため `Ctrl+C` で停止してから以降を実施してください。

</Callout>


tmux をインストールします。
```bash
sudo apt update && sudo apt install tmux -y
```

リレー用の tmux セッションを作成し、その中でリレーを起動します。
```bash
tmux new -s relay
```

セッション内でリレーを起動します。
```bash
nix run github:input-output-hk/ouroboros-leios#leios-testnet-relay
```

<Callout type="info" title="ダッシュボードの操作">

- process-compose の画面が表示され、`node` や `tip-watcher` などのプロセスが一覧表示されます。
- **マウスまたは矢印キー**でプロセスを選択し、各プロセスのログ（ノードの同期ログを含む）を確認できます。
- `tip-watcher` ペインでチェーンの同期状況をリアルタイムに確認できます。

</Callout>


セッションから抜ける（デタッチ）には、`Ctrl + b` を押してから `d` を押します。  
> デタッチしてもリレーは **バックグラウンドで動作し続けます。** SSH接続を切断しても停止しません。

再度ダッシュボードを表示する（アタッチ）には次を実行します。
```bash
tmux attach -t relay
```

<Callout type="info" title="同梱される監視スタック（Grafana）">

`leios-testnet-relay` はノードに加えて Grafana / Prometheus / Loki / tip-watcher を起動します。  
`http://<サーバーIP>:3000` で Grafana ダッシュボードにアクセスできます。  
> リモートサーバーの場合は、SSHポートフォワード（`ssh -L 3000:localhost:3000 ...`）経由でのアクセスを推奨します。ポートを直接公開する場合はファイアウォールで接続元を制限してください。

</Callout>


<Callout type="warn" title="サーバー再起動時の自動起動について">

tmux セッションは **サーバー再起動では復元されません。** 再起動後は再度 `tmux new -s relay` → `nix run ...` で起動してください。  
**完全な自動起動が必要で、対話ペインが不要な場合**は、process-compose を非対話モード（TUI無効）で systemd 登録する方法もあります。  
ただしその場合、ペイン画面は使えないため、状態確認は **Grafana（`:3000`）** や下記の `cardano-cli query tip` を使用してください。

</Callout>


## 6. 同期状況の確認 [#sec-6]

ダッシュボード以外からノードの状態を確認する場合は、別のターミナルで以下を実行します。

**`cardano-cli` で同期状況を確認**

```bash
nix develop github:input-output-hk/ouroboros-leios#dev-testnet --command \
  cardano-cli query tip
```
> `block` / `slot` / `syncProgress` が増えていけば同期中です。`syncProgress` が `100.00` で完全同期です。

**ノードのログファイルを直接確認**

```bash
tail -f "$WORKING_DIR/node.log" | grep -E 'Leios|CertRB'
```
> Leios 固有のイベント（ブロック生成・証明など）をフィルタ表示します。


<Callout type="info" title="便利なエイリアス設定">

```bash
echo "alias rattach='tmux attach -t relay'" >> $HOME/.bashrc
echo "alias rnode='tail -f \"\$WORKING_DIR/node.log\"'" >> $HOME/.bashrc
echo "alias rntip='nix develop github:input-output-hk/ouroboros-leios#dev-testnet --command cardano-cli query tip'" >> $HOME/.bashrc
source $HOME/.bashrc
```

> `rattach`…ダッシュボードに再接続／`rnode`…ノードログ表示／`rntip`…同期状況確認

</Callout>


<Callout type="warn" title="初回のチェーン同期">

ジェネシスからの同期には時間がかかります。**同期が完了するまで** プール登録などの手順には進めません。  
次は [BPノードの構築](/cardano/leios-testnet2/bp-setup) に進んでください。

</Callout>
