# トポロジー JSON 生成フォーム仕様書

ステータス: 実装済み

このファイルは開発用の仕様書です。Fumadocs の読み込み対象である `content/docs` の外に配置し、公開ドキュメントのビルドには含めません。

## 1. 配置と生成対象

次のページのトポロジーファイル設定箇所に、共通コンポーネントとして配置します。

- `content/docs/cardano/operation/node-update.mdx`
- `content/docs/cardano/setup/relay-bp-setup.mdx`

フォームの先頭に「リレー用」「BP用」の切り替えボタンを設け、選択した用途に必要な入力欄だけを表示します。

リレー用では「トポロジーを作成するリレー」のプルダウンを表示し、「リレー1用」「リレー2用」を選択します。初期値はリレー1用です。出力見出しにも選択したリレー番号を表示します。

リレー1用ではリレー2の IP・ポート、リレー2用ではリレー1の IP・ポートを入力するよう案内します。それ以外の自リレーも「＋ 自リレーを追加」で登録できますが、生成対象自身は除くことを明記します。作成対象の切り替え時は誤った接続先の流用を防ぐため、自リレー欄を空の1行（ポート `6000`、`advertise: true`）に戻します。BP・外部リレー・Peer Snapshot パスは保持します。

先頭の自リレー欄のラベルも、リレー1用では「リレー2」、リレー2用では「リレー1」に切り替えます。追加の欄は「その他の自リレー 1」から順に表示します。

## 2. 入力フォーム

| 入力欄 | リレー用 | BP用 | 出力先 |
| --- | --- | --- | --- |
| BP の IP・ポート | 表示・1台 | 非表示 | `localRoots` |
| 自リレーの IP／DNS・ポート | 表示・追加／削除可能 | 表示・追加／削除可能 | `localRoots` |
| 外部リレーの IP／DNS・ポート | 表示・追加／削除可能 | 非表示 | `publicRoots` |

- 自リレーは、自分が管理するリレーを指します。
- リレー用では、生成対象ノード自身を除いた自リレーを登録します。
- 自リレー・外部リレーそれぞれに「＋ リレーを追加」と行ごとの削除ボタンを設けます。
- BP用では、自リレーを1台以上登録します。
- BP用の初期表示は「リレー1」「リレー2」の2行とします。各行のポートは `6000`、`advertise` は `true` とし、追加・削除も可能です。BP用とリレー用の自リレー入力は別々に保持し、用途を切り替えても入力内容を復元します。
- リレー用では、BP を必須とし、他の自リレー・外部リレーは任意とします。
- BP の IP・ポートは空欄、自リレー・外部リレーのポートは `6000` を初期値にします。
- BP の入力欄に、BP ノード上で `startBlockProducingNode.sh` の `PORT=` を確認するコマンドを表示します。コピーボタンはコマンドボックス右上のアイコンのみとし、コピー成功時はチェックアイコンに切り替えます。
- 外部リレー（publicRoots）には「通常は追加しなくても問題ありません。必要な場合のみ登録してください。」と案内を表示します。

## 3. advertise の設定

| 接続先 | 初期値 | 操作 |
| --- | --- | --- |
| BP | `false` | 固定値として表示 |
| 自リレー | `true` | `true`／`false` のプルダウン |
| 外部リレー | `false` | 固定値として表示 |

自リレーごとのプルダウンの下に「この接続先を他のノードに知らせるか。デフォルトは true」という説明を表示します。

BP用を選んだ場合も、自リレーの `advertise` は選択可能です。`false` 固定なのは、接続先が BP または外部リレーの場合です。

## 4. JSON の生成ルール

| 項目 | ルール |
| --- | --- |
| `localRoots` | BP と自リレーを格納 |
| `publicRoots` | 外部リレーを格納。未登録なら `[]` |
| グループ化 | 各 Roots 内で、`advertise` が同じ接続先を同じ `accessPoints` にまとめる |
| `trustable` | `localRoots` の各グループに `false` を設定 |
| `hotValency` | `localRoots` の各グループの接続先数を設定 |
| `publicRoots` の属性 | `accessPoints` と `advertise` のみ |
| ポート | JSON の数値として出力 |

例えば、BP と自リレーの両方が `advertise: false` なら、同じ `localRoots` グループにまとめます。外部リレーは、値が同じでも `localRoots` とは混ぜません。

初版では `trustable` を固定し、個別の変更欄は設けません。

## 5. 用途別の設定

既存ドキュメントの Genesis Mode 構成に合わせます。

| 項目 | リレー用 | BP用 |
| --- | --- | --- |
| `peerSnapshotFile` | 指定したファイルパスを出力 | 出力しない |
| `useLedgerAfterSlot` | 既存手順の値 `194140785` | `-1` |
| `publicRoots` | 登録した外部リレー | `[]` |

リレー用では、Peer Snapshot ファイルのパスを入力する欄を表示し、初期値を `$NODE_HOME/${NODE_CONFIG}-peer-snapshot.json` にします。

入力欄の下に「通常はこのままで問題ありません。独自のパスを採用している場合は変更してください。」と表示します。この案内は入力エラーがある場合も表示します。

`$NODE_HOME`・`${NODE_CONFIG}` などの環境変数は、フォーム入力と生成コマンド内ではそのまま保持します。`$変数名` と `${変数名}` の形式を受け付け、対象ノードでコマンドを実行したときに展開します。実際の絶対パスを直接入力することもできます。BP用にはこの欄を表示しません。

## 6. 出力と入力チェック

- JSON を含むファイル作成コマンドを出力し、入力に応じてプレビューを更新します。
- コマンドは折りたたまずに表示し、「コマンドをコピー」を用意します。
- 出力欄はファイル作成コマンドとコピーボタンのみとし、JSON 単体の表示・コピー・ダウンロードは提供しません。
- 保存先は `"${NODE_HOME}/${NODE_CONFIG}-topology.json"` とし、環境変数を保持します。
- ヒアドキュメントは環境変数を展開する形式にします。環境変数以外のシェル特殊文字はエスケープして、入力内容をコマンドとして実行しないようにします。
- 実行前に対象ノードで `NODE_HOME`・`NODE_CONFIG` と、パスに使用するその他の環境変数を設定します。
- 必須項目、IP／DNS の形式、ポートが `1`〜`65535` の整数であることを確認します。
- 同一アドレス・ポートの重複登録を検出します。
- Peer Snapshot パスは絶対パス、または環境変数で始まるパスとし、未入力や不正な変数構文・制御文字を検出します。
- 入力エラーは該当欄に表示し、解消するまでコマンドのコピーを無効にします。
- 非表示になっている用途の入力値は、生成結果に含めません。

## 7. 入力情報の扱い

処理はブラウザ内で完結し、入力した IP などをサーバーへ送信しません。初版では入力値を永続保存せず、ページ再読み込みでリセットします。

フォームには「入力内容はSJGサーバーには送信・保存されず、再読み込みでリセットされます。」と表示します。
